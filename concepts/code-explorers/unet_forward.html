Where it sits in the sampling algorithm

Ho et al. (2020), Algorithm 2, written in the survey's notation. This whole page is row 3, one function call.

Everything on this page happens inside row 3's one call to \(\epsilon_\theta\). Cross-attention (a separate page) is one sub-step inside the down, mid and up blocks shown here; so is every residual and self-attention block. This page skims the architecture's shape, not every layer's own math.

What this means for your project

encoder_hidden_states enters this function once (line 1103's processing step) and is then handed, unchanged after that point, to every cross-attention call inside every down, mid and up block. Swap what the denoising loop passes in as encoder_hidden_states, and every one of those calls attends to something else; nothing inside this function needs to change.

down_block_res_samples is the only place spatial information crosses from the encoder half to the decoder half outside of emb and encoder_hidden_states. ControlNet (a separate project pattern entirely) works by adding to exactly these tensors, at line 1162's addition, before the up loop ever runs.

Seen whole

A noisy latent and a prompt go in on the left; a noise prediction, the same shape as the latent, comes out on the right.

\[\underbrace{x_t}_{\text{sample}}\ \xrightarrow{\text{conv\_in}}\ \underbrace{h_0\to h_1\to\cdots\to h_N}_{\text{down\_blocks, resolution halves each time}}\ \xrightarrow{\text{mid\_block}}\ \underbrace{h_N'\to\cdots\to h_0'}_{\text{up\_blocks, skip connections from } h_i}\ \xrightarrow{\text{conv\_out}}\ \underbrace{\hat\epsilon}_{\text{same shape as }x_t}\]

The shape, drawn

The same funnel every convolutional network since LeCun's draws: resolution shrinks, channel depth grows, then both reverse. Tap any stage for what's actually happening there, not just its code name.

Code terms

Names for places in the code. Each points at exactly one location.

self.down_blocks
A nn.ModuleList, SD 1.5's UNet has 4: the first three are CrossAttnDownBlock2D (resnets plus cross-attention, each halving spatial resolution), the last is a plain DownBlock2D (resnets only, no attention, no further downsampling). The if hasattr(..., "has_cross_attention") check at line 1137 is what picks between the two call shapes.
self.mid_block
One UNetMidBlock2DCrossAttn for SD 1.5: resnets and cross-attention at the UNet's lowest resolution, no further down- or up-sampling. Line 1172 checks has_cross_attention the same way the down and up loops do; for SD 1.5 this is always true. What makes it different from every down or up block: it is the only block that does not resize sample at all (no halving, no doubling), it is a single instance rather than one of a ModuleList of 4 (there is only one bottleneck), and it contributes nothing to down_block_res_samples (its output is handed straight to the first up block, not stored as a skip connection). At the lowest resolution each spatial position covers the largest share of the original image, so self-attention here mixes information across the most "zoomed out" view the network ever computes, before the up_blocks start re-localizing it.
self.up_blocks
The mirror of down_blocks: 4 blocks, the first is a plain UpBlock2D, the remaining three are CrossAttnUpBlock2D. Each one also takes res_samples, the matching skip-connection tensors sliced off down_block_res_samples at lines 1199 to 1200.
ControlNet / T2I-Adapter / GLIGEN branches
Three different ways external code can inject tensors into this function: mid_block_additional_residual and down_block_additional_residuals (ControlNet, lines 1159 to 1169 and 1192 to 1193), down_intrablock_additional_residuals (T2I-Adapter, lines 1140 to 1141 and 1184 to 1190), and cross_attention_kwargs["gligen"] (lines 1110 to 1114). All three are None in SD 1.5's own pipeline; none of their lines are pinned as run on this page, only named here.

Diffusion terms

The ideas the math is built from.

U-Net encoder/decoder with skip connections
The survey's own description, no equation number: "the encoder consists of a series of residual and self-attention blocks and downsamples the input image... the decoder mirrors this structure, gradually upsampling... with residual connections between blocks that preserve gradient flow." "Residual connections" here is the same thing most people mean by "skip connections": a tensor carried across from an earlier layer and combined back in later, bypassing everything in between. The formal shape, in one line: down_blocks is the encoder (compresses: each block roughly halves spatial resolution and increases channel count), mid_block is the bottleneck (no resizing at all, just refinement at the lowest resolution), up_blocks is the decoder (reconstructs: each block roughly doubles resolution back, using a skip connection to recover detail the compression discarded). down_block_res_samples is exactly what carries those skip connections from encoder to decoder; see its own Code terms entry for how.
Sinusoidal timestep embedding
The survey's own description, no equation number: "the diffusion timestep t is specified by adding a sinusoidal positional embedding in each residual block." Computed once, at line 1081 to 1082 (get_time_embed, time_embedding), then handed to every down, mid and up block as emb. Derivation 3 opens the actual formula.

What is checked, and how

Code and line numbers: read from diffusers v0.40.0, downloaded from PyPI in this environment (pip download diffusers==0.40.0, then read with Python's own file reader for exact whitespace) rather than recalled. Every pinned line on this page matches the real file exactly; the gaps between pinned lines are real gaps (skipped code), marked as such in the code pane, not glossed over.

Which branches SD 1.5 actually takes: has_cross_attention being true for the first three down blocks, the mid block, and the last three up blocks is the standard SD 1.5 UNet shape, consistent with the block counts named in the X-Ray; the exact per-block channel counts and resolutions were not fetched from a live SD 1.5 config in this environment (Hub-style hosts are blocked by this sandbox's network policy), so no specific channel numbers are stated on this page, only the shape of the pattern.
