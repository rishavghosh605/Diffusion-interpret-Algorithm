How a prompt becomes prompt_embeds

A string goes in. CLIP's tokenizer and text encoder turn it into a tensor cross-attention (a separate page) can read. This page is that path, and the parallel path a negative prompt takes to make classifier-free guidance possible at all.

Stage A of your SD 1.5 X-Ray, prompt encoding. diffusers v0.40.0, pipeline_stable_diffusion.py lines 332 to 512, StableDiffusionPipeline.encode_prompt. This is a skim, not a full dive: the code pane shows SD 1.5's real path only, skipping (never pinning as run) the LoRA scale setup, textual inversion token conversion, the clip_skip branch, and both error-raising branches. Notation follows the survey by Fuest et al. (2024) for classifier-free guidance; the tokenizer and text encoder themselves are CLIP (Radford et al. 2021), which the survey doesn't cover.

Called once per __call__, before the denoising loop (a separate page) starts, as self.encode_prompt(prompt, device, num_images_per_prompt, self.do_classifier_free_guidance, negative_prompt, ...). Its two return values are concatenated into one batch (torch.cat([negative_prompt_embeds, prompt_embeds])) by the caller, not by this function; that concatenation is what the denoising loop page's "noise prediction split into two halves" is the other side of.

How encode_prompt runs

Where it sits in the sampling algorithm

Ho et al. (2020), Algorithm 2, written in the survey's notation. This page runs once, before the loop, not inside any row.

This function has no row of its own: it runs once, before __call__'s loop even starts, to produce the encoder_hidden_states that row 3's \(\epsilon_\theta(x_t,t)\) reads on every single iteration. Nothing in Algorithm 2's own notation names the prompt at all; \(c\) (the conditioning signal) is implicit in \(\epsilon_\theta\).

Derive it on paper

The first checks the actual 77-token limit against CLIP's own config. The second asks why a negative prompt needs its own full encode_prompt call instead of just negating a vector. The third opens clip_skip, a black box here.

What this means for your project

This function is the only place a prompt string ever gets read. Everything downstream, cross-attention, the UNet, the denoising loop, works entirely in terms of the resulting tensor, prompt_embeds. Replacing what this function returns (bypassing the tokenizer and CLIP entirely, and handing your own tensor to prompt_embeds, the function's own optional argument) is a documented, supported way to inject a representation the tokenizer couldn't produce.

negative_prompt_embeds defaults to encoding the empty string "", not nothing: classifier-free guidance always has two embeddings to push apart, even when you never set negative_prompt yourself.

Code terms

Names for places in the code. Each points at exactly one location.

self.tokenizer
CLIP's tokenizer (CLIPTokenizer). Pads or truncates every prompt to exactly model_max_length tokens (77 for SD 1.5's CLIP), lines 396 to 402. padding="max_length" means a 3-word prompt and a 70-word prompt both produce the same shape.
self.text_encoder
CLIP's text transformer (CLIPTextModel). Called at line 423 with no further options by default (clip_skip=None); returns a tuple whose first element, indexed at the same line, is the per-token hidden states used as prompt_embeds.
clip_skip
An optional int, None by default. When set, reads an earlier transformer layer's hidden state instead of the final one (lines 426 to 437, skipped on this page's pinned path). Derivation 3 opens what that actually changes.
attention_mask (this function's own, not cross-attention's)
Always None for SD 1.5: CLIP's config does not set use_attention_mask, so the hasattr check at line 417 (and 487) is always false. Every one of CLIP's 77 positions, including padding, is attended to equally; nothing marks padding as "discard."

Diffusion terms

The ideas the math is built from.

Classifier-free guidance (CFG)
Needs two embeddings to work at all: a conditional one (prompt_embeds, from the actual prompt) and an unconditional one (negative_prompt_embeds, from negative_prompt or, by default, the empty string). The denoising loop (a separate page) runs the UNet on both, then pushes the result away from the unconditional prediction, toward the conditional one, scaled by guidance_scale.
CLIP (Radford et al. 2021)
Contrastive Language-Image Pretraining. SD 1.5 uses only its text tower here (self.text_encoder, self.tokenizer): a 77-token context, 768-dimensional hidden states, the same CLIP ViT-L/14 checkpoint used across the whole SD 1.5 family. Not covered by the survey (Fuest et al. 2024), which treats the text encoder as an opaque \(E(c)\).
