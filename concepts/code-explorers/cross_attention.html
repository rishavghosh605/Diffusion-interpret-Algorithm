What makes attention "cross"

One function computes both self-attention and cross-attention. The only difference is which tensor supplies the keys and values: the image's own features, or the prompt's. This page is that function.

Notation follows the survey by Fuest et al. (2024) for the conditioning concept, plus Vaswani et al. (2017) for the attention formula itself, which the survey doesn't restate.

What this means for your project

Cross-attention is the one place in the whole pipeline where the prompt's embeddings touch the image's features directly. Swap what encoder_hidden_states holds at line 1148 and 1149, and every self.attn2 call in the UNet attends to something else instead, with no other code change.

Self-attention (self.attn1, encoder_hidden_states=None) never sees the prompt at all: it is the image's spatial features attending to themselves, the same function running the other branch of the if at line 1143.

Terms on this page

Each term means exactly one thing. Underlined terms elsewhere on the page link here.

Code terms

Names for places in the code. Each points at exactly one location.

AttnProcessor vs AttnProcessor2_0
Two implementations of the same math. AttnProcessor (shown on this page, lines 1141 to 1162) computes query, key, value and the softmax explicitly in Python/PyTorch ops. AttnProcessor2_0 instead calls torch.nn.functional.scaled_dot_product_attention, a single fused kernel that does the same thing faster. Attention.__init__ (line 307) picks AttnProcessor2_0 automatically whenever it's available, which it is on any PyTorch 2.0 or later install; so SD 1.5 running on a current PyTorch almost certainly executes the fused version, not the one shown here. This page pins the explicit one because it is the one that shows the actual formula instead of hiding it inside a kernel; the two compute the same result.
attn.get_attention_scores
The call this page treats as a black box at line 1155. Computes \(QK^\top\cdot\text{scale}\) with torch.baddbmm, then a softmax. Derivation 1 opens it.
head_to_batch_dim / batch_to_head_dim
A pure reshape, no new math: merges the head dimension into the batch dimension before the attention matmuls (lines 1151 to 1153), then splits it back out afterward (line 1157). Exists so one torch.bmm call computes all heads' attention at once instead of looping over them.
attn.norm_cross
An optional extra normalization on encoder_hidden_states before it becomes key and value, line 1146. Off by default (cross_attention_norm=None in Attention.__init__); SD 1.5 does not use it.

Diffusion terms

The ideas the math is built from.

Scaled dot-product attention, Vaswani et al. 2017 Eq. 1
\(\mathrm{Attention}(Q,K,V)=\mathrm{softmax}\big(QK^\top/\sqrt{d_k}\big)V\). Not restated in the survey (Fuest et al. 2024), which only describes cross-attention's role in conditioning, not the mechanism itself; this page cites the original Transformer paper for the formula.
Cross-attention as conditioning
The survey's own framing (no equation number): a conditioning signal \(c\) is preprocessed by an encoder into \(E(c)\), then injected into the denoising network via cross-attention. On this page, \(c\) is the prompt, its encoder is CLIP (a separate page, not yet built), and \(E(c)\) is encoder_hidden_states, read in directly at line 1148 and 1149 with no further processing by this function.
Query, key, value
Three learned linear projections of the input. Query always comes from hidden_states (the image). Key and value come from whichever tensor is encoder_hidden_states at the time: the image itself, for self-attention; the prompt, for cross-attention. The only architectural difference between the two is this one substitution.
Heads, head dimension
Multi-head attention splits each of Q, K, V's channel dimension into several smaller, independent pieces ("heads"), runs attention separately per head, then concatenates the results back together. Attention.__init__'s defaults are heads=8, dim_head=64 when not overridden; SD 1.5's UNet overrides these per block and the exact values were not confirmed in this environment (network blocked). The shapes below are illustrative of the pattern, not a fetched config.
